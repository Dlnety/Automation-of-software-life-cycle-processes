# StudentProgress

Минимальный, но рабочий прототип веб-приложения для учета успеваемости студентов.

## Реализовано

- Python + Flask;
- Oracle Database через `python-oracledb`;
- роли «Учебный отдел» и «Преподаватель»;
- авторизация и ограничение маршрутов по роли;
- добавление и изменение студентов;
- добавление и изменение учебного плана;
- подсчет студентов по форме обучения;
- сведения по дисциплине: часы, семестр, специальность, форма отчетности;
- журнал успеваемости: добавление и изменение оценок;
- PL/SQL-пакет `STUDENT_PROGRESS_PKG`;
- пользовательские исключения `RAISE_APPLICATION_ERROR`;
- ограничения БД, триггер проверки оценок и аудит изменений;
- тестовые данные;
- Docker Compose;
- адаптивный русскоязычный интерфейс.

## Архитектура

Приложение разделено на три простых слоя:

1. `app.py` — HTTP-маршруты, авторизация, проверка ролей и подготовка данных для интерфейса.
2. `db.py` — работа с Oracle и демо-данными, транзакции и преобразование ошибок БД в понятные сообщения.
3. `STUDENT_PROGRESS_PKG` в Oracle — основные изменяющие операции предметной области. Ограничения и триггеры БД дополнительно контролируют целостность и аудит.

Основные сущности: специальности, группы, студенты, дисциплины, учебный план, журнал успеваемости, пользователи и аудит.

## Краткое соответствие ТЗ

Учебный отдел работает со студентами и учебными планами, считает студентов по форме обучения и получает сведения о дисциплине. Преподаватель просматривает студентов и дисциплины, добавляет и изменяет оценки. Доступ к разделам определяется ролью. Полный чек-лист находится в `TZ_CHECKLIST.md`, сценарии приемки — в `ACCEPTANCE_TESTS.md`.

## Самый простой запуск для лабораторной №2 — без Oracle

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python app.py
```

По умолчанию в `.env.example` стоит `DEMO_MODE=1`.
Открыть: `http://127.0.0.1:5000`.

Демо-пользователи:

- `study / study123` — Учебный отдел;
- `teacher / teacher123` — Преподаватель.

## Запуск с Oracle

SQL выполняется строго по порядку:

1. `sql/00_reset.sql`
2. `sql/01_schema.sql`
3. `sql/02_package.sql`
4. `sql/03_triggers.sql`
5. `sql/04_seed.sql`

В `.env` установить:

```text
DEMO_MODE=0
DB_USER=student_app
DB_PASSWORD=student_app_password
DB_DSN=localhost:1521/FREEPDB1
```

Затем запустить `python app.py`.

## Docker Compose

Для контейнерного запуска:

```bash
docker compose up --build
```

Первый старт Oracle занимает заметно больше времени. SQL-скрипты подключены как init-скрипты и выполняются при первичном создании тома.

> Учебные пароли и секреты в этом репозитории демонстрационные. Для реального развертывания их необходимо заменить.
